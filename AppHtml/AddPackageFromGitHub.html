Add a package from GitHub

The Add Package field takes one string, and that string is two things joined: the repository's clone URL, and the path to the .sws file inside that repository. Everything below is how to assemble it without typing any of it by hand.

What you are building

Clone URL — copied from the repo
A slash you add yourself
Path to the .sws inside the repo
STEP 1

Open the repository

Go to the library's page on GitHub — the front page of the repo, not a file view.

github.com/NilsSve/Library-DUF
AppSrc
DDSrc
RDC-DUF-Library.sws
STEP 2

Copy the clone URL

Press the green <> Code button and copy the HTTPS address. It ends in .git — that ending matters, it is what marks the string as a git package.

Paste it straight into the Add Package field.

Code
HTTPS
https://github.com/NilsSve/Library-DUF.git
STEP 3

Copy the right .sws path

Back on the repo page, find the .sws file and copy its name. A library usually ships several — one per DataFlex release, and a Dev twin beside each — so this is a choice, not just a copy.

Take the Library file for the target release, not the Dev one. And if it sits in a folder, the folder is part of what you copy.

Library-DUF
DUFDev25.0.sws
DUFDev26.0.sws
DUFLibrary25.0.sws
RDC-DUF-Library.sws
STEP 4

Join them with a slash

In the Add Package field, put the caret at the end of the URL you pasted, type one forward slash, then paste the file path after it.

This is the step people miss. Without the slash the string is just a repo, and DFRefactor has no way to know which workspace file inside it to use.

Package
https://github.com/NilsSve/Library-DUF.git/RDC-DUF-Library.sws
STEP 5

Press OK

DFRefactor records the dependency and hands the file to df-cli, which fetches the repo into the workspace's DfPkg folder.

One package can bring others. DUF depends on RDCToolsLib, DFAbout and vWin32fh, so all four appear in DfPkg from this single string — you do not add them yourself.

If the library was previously a folder under Libraries\, the dialog then offers to rename the old folder out of the way.

Package
https://github.com/NilsSve/Library-DUF.git/RDC-DUF-Library.sws
Cancel OK

The .sws is not always at the top

Copying just the file name works only when the .sws sits in the root of the repository. Several libraries keep theirs in a subfolder, and then the subfolder is part of what you paste.

vWin32fh is the one to remember: its workspace file lives in StudioLibrary/, so the string needs that folder in it or df-cli will not find the file.

Three that are known to work

DUF — .sws in the repo root, and it brings three more packages with it
https://github.com/NilsSve/Library-DUF.git/RDC-DUF-Library.sws
VDFQuery20 — .sws in the repo root; this build depends on vWin32fh and brings it with it
https://github.com/NilsSve/VDFQuery20.git/VDFQuery20.sws
vWin32fh — .sws inside a subfolder
https://github.com/NilsSve/Library-vwin32fh.git/StudioLibrary/vWin32fh-Library-DF26.0.sws
The same field also accepts a publisher/package#version for a DataFlex system package, or a path to a local .sws. Packages need the DataFlex 26 JSON workspace format; an INI workspace has nowhere to record one.
