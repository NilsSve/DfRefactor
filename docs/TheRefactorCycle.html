The Refactor Cycle

A workspace is modernized in several rounds, not in one pass. Each round finds what needs to be changed, fixes what can be fixed automatically, and lists the rest together with the reason. Fixing some findings reveals new ones, so a round can find things that the previous round could not. This is why the number of findings goes down from round to round, instead of dropping to zero at once.

How to use the Program describes a complete session, step by step. The topics in this chapter describe each part of a round, in the order in which you use them.


One round, step by step

  1. Check - Compile + Analyze does two things when you press it: it compiles the program with the compiler of the version you are moving to, and it scans your source code.
  2. The results are shown on three tabs at the bottom of the window. Each tab answers a different question:
    • Compiler Output — what did the compiler actually say?
    • Analyzer — which of these messages can DFRefactor fix?
    • Manual Changes — which changes did DFRefactor not make, and why?
  3. Run Plan on the Analyzer tab makes the changes that you approve. A change that a function does not make is listed on the Manual Changes tab instead.
  4. Press Check again. This starts the next round, which can find work that the previous round could not.

The cycle is finished when a Check finds nothing more that can be fixed. What remains is then either for information only, or manual work that is listed on the Manual Changes tab.


Running the source scan on its own

Step 1 above both compiles and scans. Analyze Source runs only the scan, for when you do not want to compile. It finds obsolete code that compiles without problems, which compiling would never show. A workspace that compiles without any messages can still contain a lot of such code. The findings are added to the compiler's rows on the Analyzer tab.


The record of all rounds

While you work, it can be hard to see how much progress you have made. Modernization Progress stores the counts from every round, so you can see how much the number of findings has gone down from the first Check to the latest one. It shows whether you are getting closer to the end, and when the number of automatically fixable findings reaches zero, it shows that DFRefactor has done all it can.
