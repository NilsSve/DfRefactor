The Refactor Cycle

A workspace is modernized in laps, not in one pass. Each lap finds what is wrong, fixes what can be fixed automatically, and leaves the rest named with a reason. Fixes unlock further findings, so a lap sees things the one before it could not — which is why the counts fall pass by pass rather than dropping to zero at once.

How to use the Program walks a whole session in the order it happens. The pages in this chapter describe the surfaces a lap passes through, in the order you meet them.


One lap, in order

  1. Check - Compile + Analyze runs two lanes on one press: it compiles the program with the compiler you are moving to, and it scans your source.
  2. The result lands on three tabs at the foot of the window, and each answers a different question:
    • Compiler Output — what did the compiler actually say?
    • Analyzer — which of that can DFRefactor fix?
    • Manual Changes — what did it decline to do, and why?
  3. Run Plan, on the Analyzer, applies the fixes you approve. Anything a function will not do goes to Manual Changes rather than being guessed at.
  4. Press Check again. That is the next lap, and it will find work the last one could not have seen.

The cycle is finished when a Check finds nothing actionable. What is left then is either informational, or the hand work waiting on the Manual Changes tab.


The scan lane, run on its own

Step 1 above scans as well as compiles. Analyze Source is that scan lane by itself, for when a compile is not what you want — it needs no build, and it finds obsolete constructs that compile perfectly well, so no amount of compiling would ever surface them. A workspace that builds cleanly can still have plenty for it to find. Whatever it finds joins the compiler's own rows on the Analyzer tab.


The record across laps

A loop is hard to judge from inside it. Modernization Progress keeps the count from every lap, so the fall from the first Check to the latest is a figure you can read rather than one you have to remember. It is what tells you the cycle is converging — and, when the auto-fixable count reaches nothing, that the tool has done what it can.
