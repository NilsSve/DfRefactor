  1. Refactoring Functions

Editor - One File

Functions of type eEditorFunction work on a whole file through the Scintilla editor control. The control is an OCX and must be visible to operate, so the editor view comes to the front on its own part-way through a run that includes one. They are slower than the line-by-line types for the same reason - the source is round-tripped through the control rather than walked in memory.


EditorNormalizeCase

Adjusts the casing of all scopes and keywords to match the casing as defined in the language configuration.

Example: procedure OnClick -> Procedure OnClick, and if (iRec <> 0) begin -> If (iRec <> 0) Begin The casing each word is normalised TO is a setting rather than this function's opinion. The spelling of every keyword and operator lives in the Editor Settings dialog, under Keywords and Operators, so the result follows your own house style.

Runs through the cScintillaEdit control, so the program's Editor view is paged while it works.

Group: Tidy Up


EditorReIndent

Reindents the source code with the number of spaces specified in the sParameter variable.

Example: a file mixing 3-space, 8-space and flush-left lines is re-indented to the size you pick.

Every line's depth is re-derived from the block structure, so a file that mixes indent styles, or whose indenting has drifted over the years, comes back at one consistent depth.

The tab size is the same setting as the tab size on the Editor Settings dialog; the two controls are linked.

Runs through the cScintillaEdit control, so the program's Editor view is paged while it works.

Group: Tidy Up

Parameter: 1, 2, 3, 4, 5, 6, 7, 8

Default: 4

Select the indent size you want to use for spaces when indenting code and when breaking a line on rewriting a single line to multiple lines.

It is the same value that can be set on the Editor Settings dialog tab size.
