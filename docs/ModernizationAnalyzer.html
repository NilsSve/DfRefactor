Modernization Analyzer

The Modernization Analyzer reads the DataFlex compiler's own warnings and errors after a test compile and maps each message to the refactoring function that fixes it. It changes nothing by itself — it is a triage list you then act on.


Getting a list

In the Test Compile dock, press Compile, then Analyze — see Test Compile. The findings load into the Analyzer tab. Analyze Source, started from the dashboard, fills the same grid from a scan of your selected source folders — obsolete commands and symbols the compiler never mentions.

The full compiler listing stays on the Output tab, and its totals can be higher: the analyzer removes diagnostics with nothing to refactor and reports the number as a muted "excluded" count.

The third tab, Manual Changes, is not a compiler view at all. It collects what a refactoring function declined to do, and why — see Manual Changes.


Reading a row

The Fix column carries the verdict:

  • Auto-fix — a refactoring function applies the fix cleanly.
  • Review — a fix is applied, but check the result afterwards.
  • Explain — no automatic fix exists; Suggested fix says what to do by hand.
  • Unknown — not mapped to a recipe yet, so the compiler's own sentence is shown instead — still the best clue you have.
  • System (read-only) — the file lies outside your workspace (a DataFlex install package), so nothing can be refactored here.

Msg# prefixes the number: W for a warning, E for an error, DS for a source-analyze finding. File and Line point at the source, and (xN) after the line number means N messages were folded into that one row — the line shown is the first of them. Refactor function names the function that will run.

Explain, Unknown and System rows are hidden by default so the actionable work stands out. Toggle Explain (Ctrl+I) reveals them.


Acting on the grid

Double-click behaves differently on a folded row: a row marked (xN) unfolds to list its occurrences (double-click again to fold it back), while any other row jumps to that source line in the editor. Right-click offers both as Locate in Editor and Toggle Unfold / Fold occurrences.

When the list looks right, press Run Plan. The Refactoring Plan - review and select before running dialog opens with the Auto-fix functions ticked, the Review ones listed but unticked — you opt in to those — plus the Affected Files: they will touch. Untick what you do not want before you proceed.

Select rows you will never act on and press Ignore Row(s): they stay out of the grid and the plan on every future analyze of this workspace, until you press Clear Ignored.


It loops

Fixes unlock further warnings, so compile and analyze again until nothing actionable is left. Every lap is recorded, so you can watch the counts fall: see Modernization Progress.

See also Refactoring Functions for what each function does, and How to use the Program for the surrounding workflow.
