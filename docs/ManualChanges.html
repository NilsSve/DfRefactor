Manual Changes

The Manual Changes tab is the third tab at the bottom of the window, beside Compiler Output and Analyzer. It lists the changes that a refactoring function could not make for you, and the reason why.

A compile never adds rows to it, so it stays empty no matter how often you press Check. Its rows come from the dashboard's Findings list.


Where the rows come from

The rows are added by the actions on a name-collision finding: Check declarations (Show declarations on some rows) and Rename it.... Three functions add rows:

  • Check declarations — the report for an ambiguous return type (error 4544) lists every declaration of the name: the ones in your workspace, and the ones in the DataFlex installation. It does not change anything. The list shows whether the solution is to rename the method or to give the declarations the same return type.
  • Rename it... — renames every call where it can tell from the source code that the object belongs to the class or one of its subclasses. Calls where this cannot be determined are listed here instead of being guessed. If the name is a global function rather than a class method, nothing is renamed automatically, and all of the work is listed here for you.
  • Convert to Get — offered as the last option, when the declarations can neither be renamed nor be given the same return type. It changes calls in expressions into Get statements, and lists the calls that it does not change, for example a call that continues on the next line, because nothing can be inserted between a line and its continuation.

The Reported by column shows the function that added the row. When that function runs again, it replaces its own rows, but it never removes the rows of another function.


Reading a row

What to change describes what needs to be changed. Why it was left for you explains why DFRefactor did not make the change. This is the most important column: it shows the difference between work that was only skipped and work that cannot be done safely without you.

The tab is brought to the front automatically when a run adds rows to it.


Working through it

  • Double-click a row, or press Enter, to open that file in the editor at the line.
  • Click a column header to sort. Sort by File to work through one file at a time, or by Why it was left for you to fix one kind of problem at a time.
  • Right-click for Copy content to Clipboard, which copies the selected rows separated by tabs, ready to paste into an e-mail or an issue, and Copy ln number to Clipboard.
  • A row is removed from the list when you run the function that added it again, not when you edit the source. Run the function again to confirm that the work is done.
  • The list is not saved when you close DFRefactor. Two of the three functions also write a report that is saved: AmbiguousCallsToFix.log.txt and FunctionReturnMismatchReport.log.txt, both in the workspace's DFRefactor_Backup folder.


How it differs from the Analyzer

The Compiler Output tab shows the compiler's complete output, and the Analyzer tab shows what the compiler found that DFRefactor can fix. Manual Changes shows what is left for you to do.
