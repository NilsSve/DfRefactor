Manual Changes

The Manual Changes tab is the third tab of the bottom dock, beside Output and Analyzer. It is a worklist of the changes a refactoring function decided it could not make for you, and the reason it stopped.

Nothing a compile does ever writes to it, so from Test Compile the tab sits empty and stays empty. Its rows come from the dashboard's Findings list.


What puts a row here

The actions on a name-collision finding — Check declarations (Show declarations on some rows) and Rename it... — are what fill this tab. Three functions file rows:

  • Check declarations — the report behind an ambiguous return type (error 4544) lists every declaration of the contested name: your workspace's, and the ones the DataFlex install itself ships. It changes nothing. The list is what tells you whether the fix is a rename or a type alignment.
  • Rename it... — the rename renames every call whose receiver it can prove belongs to the class family. Call sites it cannot type from the source are listed here rather than guessed at. Where the name turns out to be a global function rather than a class method, nothing is renamed automatically and the whole job is handed over.
  • Convert to Get — offered last, when the declarations can be neither renamed nor aligned. It rewrites expression-style calls into Get statements, and lists the calls it will not touch: one split over two lines, for instance, where nothing can be inserted between a line and its continuation.

Rows carry the function that reported them in Reported by. Running that function again replaces its own rows and never discards another's.


Reading a row

What to change says what is needed. Why it was left for you says what stopped the tool — and that is the column that matters: it separates work that was merely skipped from work that cannot be done safely without you.

The tab brings itself forward whenever a run files something on it.


Working through it

  • Double-click a row, or press Enter, to open that file in the editor at the line.
  • Click a column header to sort. Group by File to work through a file at a time, or by Why it was left for you to clear one kind of problem in one pass.
  • Right-click for Copy content to Clipboard — the selected rows, tab-separated, ready to paste into a mail or an issue — and Copy ln number to Clipboard.
  • A row leaves the list when you run the reporting function again, not when you edit the source. Re-run it to confirm the work is done.
  • The list itself is not kept when you close DFRefactor. Two of the three write a report that is: AmbiguousCallsToFix.log.txt and FunctionReturnMismatchReport.log.txt, both in the workspace's DFRefactor_Backup folder.


A different question from the Analyzer's

The Output tab is the compiler's own listing, and the Analyzer tab is what the compiler found that DFRefactor can fix — see Modernization Analyzer. Manual Changes answers the third question: what is left for you.
