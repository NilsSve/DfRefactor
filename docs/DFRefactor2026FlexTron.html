DFRefactor 2026 FlexTron

This release replaces the program's user interface and puts a whole modernisation run in order behind it. Earlier releases gave you a list of refactoring functions and left the question of which ones your workspace needed up to you. This one answers that question first, then applies the functions.


A new user interface

The desktop windows are now rendered with FlexTron, so the program draws its own surface rather than relying on the Windows controls.

  • Start Center — the opening screen: pick a workspace and see what state it is in before anything runs.
  • Guided Dashboard — the run as a trail, one step at a time, for a workspace you have not modernised before.
  • Manual Dashboard — the same tools without the trail, for when you already know which conversion you want.
  • A light and a dark theme, following the DataFlex framework's own theme setting. Change in the Program Settings dialog.
  • The current workspace is named in the header of every view, so a run can never be aimed at the wrong one by accident.


A run now has an order

The guided plan walks you through, and the tour on the Start Center shows each step on screen:

  1. Pick the DataFlex version you are moving to. Everything else depends on it, so it comes first — you choose a compiler, and the version is read from it.
  2. Open the workspace, then copy it and work on the copy. The copy gets its own .sws for the version you are moving to, so the original keeps building as it always did.
  3. Match the libraries — and, from DataFlex 26, the packages.
  4. Set the scope: which folders, and which file types.
  5. Check. One Check compiles the program with your target compiler and analyzes what comes back: every error and warning the compiler emits is matched to the refactoring function that fixes it. A separate Analyze Source pass finds obsolete constructs that still compile, so they raise no message at all.
  6. One list, ordered by what to do first: what the tool can fix for you, then what breaks the build, then what needs a human decision, then what has to be migrated by hand.
  7. Approve the plan, and it runs. The auto-fixable group becomes a plan you read before anything is written — which functions will run, and what each is set to. Untick anything you are not ready for.

The plan is saved with the workspace, so a session can be closed and resumed, and each pass is recorded — the count going down is visible from one pass to the next.


Workspace libraries and packages

  • Libraries — the [Libraries] section of a workspace .sws as an editable list, showing what each entry resolves to and what depends on it.
  • DataFlex 26 packages — browse the package registry, add a package, and uninstall one, all through df-cli. A package's details, including its licence, are shown before it is installed.
  • Convert a workspace from the older INI format to the DataFlex 26 JSON format, which is what packages require.


Undoing a run

Refactoring rewrites source files. Every file changed by a run is copied to a backup folder first, and Undo Refactoring moves the backups back to their original folders. Backups are kept for a number of days you set in Program Settings; nothing is removed before then. See Program Settings.
