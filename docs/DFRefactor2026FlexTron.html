DFRefactor 2026 FlexTron

This release replaces the program's user interface, and the modernization is now done in a fixed order. In earlier releases you got a list of refactoring functions and had to decide yourself which ones your workspace needed. This release first finds out which functions are needed, and then runs them.


A new user interface

The windows are now drawn with FlexTron, so the program draws its own user interface instead of using the standard Windows controls.

  • Start Center — the first screen: select a workspace and see its current state before anything is run.
  • Guided Dashboard — guides you through the work one step at a time, for a workspace that you have not modernized before.
  • Manual Dashboard — the same tools without the step-by-step guide, for when you already know which conversion you want.
  • A light and a dark theme, following the DataFlex framework's own theme setting. Change in the Program Settings dialog.
  • The name of the current workspace is shown in the header of every view, so that you cannot run the refactoring on the wrong workspace by mistake.


What a full Refactor cycle does, in order

Each step depends on the previous one, which is why the guided flow uses a fixed order. The tour on the Start Center shows the same steps on screen:

  1. Pick the DataFlex version you are moving to. All other steps depend on it, so it comes first. You select a compiler, and DFRefactor reads the version from it.
  2. Open the workspace, then copy it and work on the copy. The copy gets its own .sws file for the version you are moving to, so the original continues to compile as before.
  3. Match the libraries — and, from DataFlex 26, the packages.
  4. Set the scope: which folders, and which file types.
  5. Check. One Check compiles the program with the compiler of the version you are moving to, and analyzes the result: each error and warning from the compiler is linked to the refactoring function that fixes it. A separate Analyze Source scan finds obsolete code that still compiles, and therefore causes no compiler messages.
  6. One list, sorted by what to do first: what DFRefactor can fix for you, then what stops the compile, then what needs your decision, and then what has to be changed by hand.
  7. Approve the plan, and it is run. The automatically fixable findings are turned into a plan that you review before any file is changed. The plan shows which functions will run, and the setting of each one. Clear the check box of anything that you do not want to run yet.

The plan is saved with the workspace, so you can close a session and continue it later. Each round is recorded, so you can see the number of findings go down from one round to the next.


Workspace libraries and packages

  • Libraries — the [Libraries] section of a workspace's .sws file, as a list that you can edit, with the folder that each entry points to and what depends on it.
  • DataFlex 26 packages — browse the package registry, add a package, and uninstall one, all through df-cli. A package's details, including its licence, are shown before it is installed.
  • Convert a workspace from the older INI format to the DataFlex 26 JSON format, which is what packages require.


Menus, the CI scan and TechStack readiness

  • A menu bar with the menus File, Edit, View, Workspace, Tools and Help. All commands are available in the menus, and the most used commands are also on the toolbars. See Menus and Toolbars.
  • The CI scan. DFRefactorFT64.exe /scan runs Analyze Source without changing any files, saves the findings as JSON and SARIF, and fails a build only when there are findings that are not in the baseline. See Command-Line Usage.
  • Export to a Batch-mode INI File can export all Modernization functions instead of only the selected ones. The Unicode64 functions are added only when you check that option. The export also writes _SCAN.ps1, which starts the CI scan, and _CI-SAMPLE.yml, a sample GitHub Actions workflow.
  • A batch run no longer changes your settings. The functions and the file filter in the ini-file are used for that run only, and your own settings are restored when the run ends.
  • TechStackReadinessReport is a new report. For each topic and file, it counts where the workspace uses features that DataFlex's TechStack (the DataFlex 27 previews) changes or does not yet support. See Report - All Files.
  • New refactoring functions, for example functions that replace obsolete error numbers, that convert legacy attribute commands to Get_Attribute and Set_Attribute, and that convert grid and popup menu subclasses to CodeJock. See Refactoring Functions.


Undoing a run

Refactoring changes source files. Before a run changes a file, the file is copied to a backup folder, and Undo Refactoring moves the backups back to their original folders. Backups are kept for a number of days you set in Program Settings; nothing is removed before then. See Program Settings.
