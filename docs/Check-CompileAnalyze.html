Check - Compile + Analyze

Check is the button that drives one modernization lap, and its sub-line says exactly what it does: compile + analyze. Press it and DFRefactor builds the program you selected, reads the compiler's own warnings and errors, and turns them into a single findings list ranked by severity.

The button stays dark until it can run, and the sub-line says what is missing — pick a program first, or choose a compiler first.


Choose the target compiler first

  • Target DataFlex version — this dashboard tile opens the Target DataFlex Version (Compiler Settings) dialog. Press Select, pick the compiler executable, then Save.
  • Why it matters — the compiler you point at is the version you are modernizing toward. Its warnings, and so the functions this workspace needs, come from that install, not from the version the code was written for. Starting a compile with none chosen offers the dialog straight away (No compiler selected).
  • Build Options: fills itself in when you Select — DataFlex 26's df-cli and the older console compiler take different flags. x86 suffix: / x64 suffix: matter only where a program's .cfg names no output suffix.
  • Pick DFComp.exe and the console compiler beside it is saved instead (Compiler adjusted): DFComp returns before the build finishes, so anything read from it describes a half-written build.


What one Check does

  1. Builds the program named under the dashboard's Select Program step — the workspace's own projects; with none chosen the first is used.
  2. Reads that build's warnings and errors, folds in a quiet scan of your selected source folders, and ranks the result into one findings list.
  3. Ticks the Cycle counter beside the button, so the figures next to it move with every press — see Modernization Progress.

Warnings are the raw material of the whole exercise, so where a program's .cfg has switched them off, DFRefactor turns them on for its own compile and restores the setting afterwards.


Where the results land

Three tabs at the foot of the window, each with its own page:

  • Compiler Output — the compiler's listing, verbatim.
  • Analyzer — the diagnostics DFRefactor can act on, and the Run Plan button that acts on them.
  • Manual Changes — what a refactoring function declined to do, and why.

The dashboard's own findings list is built from the Analyzer's rows, so an ordinary lap can be run without opening any of them.


The same two steps, without the dashboard

The compile bar carries them as separate buttons — Compile, then Analyze — for when you want them apart:

  • Show or hide the bar with the Show Compile pane toolbar item, or Ctrl+M in the editor view. F5 there saves the current file and starts the same compile.
  • While a build runs the chip reads Stop Compile, which terminates the compiler and discards the partial output.
  • A compiler older than the workspace's DataFlex version is refused before launch.
  • The .err and .prn land beside the program source, the executable in the workspace's program folder. The bar carries the verdict, e.g. Success: <program> compiled cleanly.


It loops

Fixes unlock further warnings, so press Check again after each run and watch the counts fall. Some diagnostics only surface once earlier ones are cleared, which is why a workspace takes several laps rather than one. It is finished when a Check finds nothing actionable.
