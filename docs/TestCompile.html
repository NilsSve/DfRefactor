Test Compile

Test Compile builds one program of the loaded workspace with a DataFlex compiler of your choice. The build is not the point: its warnings and errors are what Analyze reads, so this is the step that produces the modernization work list.


Choose the target compiler first

  • Target DataFlex version — this dashboard tile opens the Target DataFlex Version (Compiler Settings) dialog. Press Select, pick the compiler executable, then Save.
  • Why it matters — the compiler you point at is the version you are modernizing toward. Its warnings, and so the functions this workspace needs, come from that install, not from the version the code was written for. Starting a compile with none chosen offers the dialog straight away (No compiler selected).
  • Build Options: fills itself in when you Select — DataFlex 26's df-cli and the older console compiler take different flags. x86 suffix: / x64 suffix: matter only where a program's .cfg names no output suffix.
  • Pick DFComp.exe and the console compiler beside it is saved instead (Compiler adjusted): DFComp returns before the build finishes, so anything read from it describes a half-written build.


Run it

  • Compile builds the program chosen under the dashboard's Select Program step — the workspace's own projects; with none chosen the first is used. While it runs the same chip reads Stop Compile, which terminates the compiler and discards the partial output.
  • Show or hide the bar with the Show Compile pane toolbar item, or Ctrl+M in the editor view; F5 there saves the file and starts the same compile. A compiler older than the workspace's DataFlex version is refused before launch.


Where the output goes

  • The Output tab streams the compiler's listing. A clean build ends with ----Compile Finished in <n> seconds ---- and ----Executable written:; warnings or errors add a - Total Warnings : / - Total Errors : summary above the messages. Double-click a message row to open that source line.
  • The .err and .prn land beside the program source, the executable in the workspace's program folder. The bar carries the verdict, e.g. Success: <program> compiled cleanly.


Then Analyze

  • Analyze lights once a compile has left output, and reads those errors and warnings into the Analyzer tab — see Modernization Analyzer — where Run Plan turns them into a refactoring run. Repeat until clean; some fixes only surface once earlier ones are made.
  • Warnings are the raw material, so if the program's .cfg switched them off, DFRefactor turns them on for its own compile and restores the setting afterwards.
