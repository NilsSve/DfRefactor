Refactoring Functions

DFRefactor's refactoring functions are described along two axes: the type, which decides what the engine hands the function and how often it is called, and the group, which says what kind of work it is. Both appear as columns in Select Functions, and both can be used to narrow the list.


What the functions run against

A function itself has no opinion about scope — that comes from how you start the run:

  • A whole workspace. Every source file under the folders picked in Select Folders that matches the Filter: on the same view. This is what both the guided route and the Manual Dashboard's Workspace mode use.
  • A single file. The Manual Dashboard's Single file entry runs the selected functions against one source file.

See How to use the Program.


Groups

The Group column says what a function is for, and the function library tile counts them:

  • Modernization — brings legacy code up to current DataFlex. The great majority of the library.
  • Tidy Up — tidies or removes: trailing spaces, dead keywords, redundant comments.
  • x64 + Unicode — 64-bit and Unicode migration readiness, both the reports and the fixes.
  • Other — anything not classified.


Types

Constrain by Type: on the Select Functions view narrows the list to one of these. Each corresponds to a MethodType declared in the function's own meta-tag, which is what tells the engine how to call it.

Standard — Line by Line
Modifies source one line at a time. The engine calls each selected function for every line of every selected file, with the line passed by reference; the function returns True if it changed the line. By far the largest type. MethodType = eStandardFunction.

Remove — Line by Line
Like Standard, but for lines that should disappear rather than change. The function returns True if the line is to be removed. MethodType = eRemoveFunction.

Editor — One File
Operates on a whole file through the Scintilla editor, for transformations that need the editor's own tokenization — re-indentation, keyword case. The editor view is activated automatically when a run includes one, because the control must be visible to work. MethodType = eEditorFunction.

Report — One File
Reports findings against a single file and changes nothing. MethodType = eReportFunction. No functions of this type ship today — the type exists for the engine to support, and for your own functions.

Report — All Files
Reports findings across all selected files at once, changing nothing. This is where the survey-style functions live. MethodType = eReportFunctionAll.

Other — One File
Receives a whole file as a string array, for transformations that need to see across lines — collapsing consecutive blank lines, finding unused locals, converting a class and its properties together. MethodType = eOtherFunction.

Other — All Files
Receives all selected files at once, for changes that must stay consistent across a workspace rather than within a file. MethodType = eOtherFunctionAll.


Parameters

Some functions take an extra value — an index number, a split style, a class-name mapping. Those appear in the Parameter column of Select Functions; double-click the cell to choose, and hover to read what each value means. A function's own page describes what its parameter does.
