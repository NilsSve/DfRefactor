Other - All Files

Functions of type eOtherFunctionAll receive a string array covering all selected files in the workspace. They are used for cross-file transformations that need a global view.


Cancel handling inside refactoring functions

If your refactoring function (especially the eOtherFunction and eOtherFunctionAll types) loops internally over many lines or files, you may want to let the user cancel without waiting for your loop to finish. Use:

Get pbUserCancelRequested of ghoEngine to bCancel

and exit your local loop when it returns True. Never call Get Cancel_Check of ghoEngine from inside a refactoring function - that is the engine's own cancel pipeline (it deactivates the status panel and shows the confirmation dialog), and calling it from your code silently consumes the cancel signal. The engine cannot then detect the cancel and the program appears to lock up while it continues processing the remaining files. The safe pbUserCancelRequested accessor is a read-only check with no side effects, so the engine's own cancel check at the file boundary still works correctly.


AlignCollidingDeclarationType

Aligns a name that is declared with more than one type to ONE type - the DF 25/26 error 4544 fix for a name that nothing outside the workspace owns, where renaming would change nothing.

sParameter is 'Name=Type', for example 'pbSilent=Boolean'.

Rewrites DECLARATION lines only (Property <type> <name>, Function <name> ... Returns <type>); no call site is touched. Changing a declared type is a semantic change - see the report first.

WHICH 4544 FIX TO PICK: rename the name when DataFlex itself holds it with a different type, because that side cannot move. Use THIS one when the disagreement is only among your own declarations - renaming all of them would simply carry the same disagreement over to the new name and clear nothing. Typical case: pbSilent declared Boolean in two of your packages and String in a third; one word makes them agree.

It is never run unasked. Changing a declared type is a semantic change, and only you know whether some site assigns a value the new type cannot hold - so the guided flow names the file, the line and both types before it runs, and the run summary lists every site it touched.

Selected without a parameter, or with anything that is not Name=Type, it changes nothing and says so in the run notes; that is a skip, not an error.

An Overloaded declaration is left alone and the run notes say how many. Its variants are MEANT to return different types - DataFlex tells them apart by parameter count - so no

4544 can arise and retyping them would change what they return.

Group: Modernization


ChangeCollidingMethodName

Renames a method that is declared with more than one return type - the DF 25/26 error 4544 fix at the DECLARATION, which a call-site rewrite cannot fully reach.

sParameter is 'OldName=NewName', for example 'Value=ValueByKey'.

Renames the declaration in every class of the family (subclass overrides included) and every call whose receiver can be PROVED to belong to one. Anything unprovable is listed on the Manual Changes tab rather than guessed at.

Renaming the declaration settles every call of the name, including calls split over two lines, calls inside a macro (reported wherever the macro is USED) and calls in DataFlex's own packages, which are never edited - on one sample workspace, 3 declarations against roughly 400 call sites.

A subclass that overrides the name is renamed too; leaving it behind would keep the workspace half-renamed and still ambiguous. Object declarations count workspace-wide

(Register_Object), while a local handle from Get Create is followed only inside its own file - an 'hTbl' in one file has nothing to do with an 'hTbl' in another.

A declaration found OUTSIDE the workspace home folder is renamed AND reported: a shared library tree can legitimately belong to this workspace and to others, which still compile against the old name.

Nothing is guessed. This runs over library code as well, so a receiver that cannot be typed from the source is reported, never rewritten.

A name declared Overloaded is refused: DataFlex picks the variant by parameter count, so several return types under it are legal and no 4544 can arise.

Group: Modernization


ChangeDFCreateMenuToCodeJock

Converts the legacy DFCreate_Menu / On_Item pull-down system to a CodeJock command-bar menu.

Standard DEO items (Request_Clear, Find_GE, Switch_Next_Area, Activate_About and 36 more) become the shipped cCJ* classes that already implement them - carrying their own localized captions - and a program's own items become cCJMenuItem with an OnExecute that sends the same message. Menu fragments pulled in by #INCLUDE are inlined, so the program becomes self-contained. The legacy block is commented out, never deleted. Only .src files are written. Returns menu items converted.

What it does not do: .mn menu FILES are a separate format and are left alone; accelerator text in a legacy caption is display text, not a real binding, so it is carried across as a comment rather than guessed into a CodeJock shortcut - add the shortcuts you want by hand; and a line inside a menu block that is not menu grammar (a property declared mid-menu) is kept COMMENTED, never dropped.

Order does not matter: it finds its own anchor - an existing cCJCommandBarSystem to nest in, otherwise the client area, bringing the command-bar system with it - so it works with or without the modern application shell, and a second run finds nothing left to convert.

Group: Modernization


RefactorDbGridTocDbCJGrid

Refactors legacy DbGrid objects to a CodeJock grid class with individual column objects.

sParameter is 'OldGridClass,NewGridClass[,NewColumnClass]' (empty = any class ending in "dbgrid", targets cDbCJGrid/cDbCJGridColumn). Returns grid objects transformed.

For each matching DbGrid object, scoped to the legacy object and never the whole file: - Renames the class to the new grid class.

  • Converts the Begin_Row / Entry_Item list into individual column child objects.
  • Maps Set Form_Width Item N to W -> Set piWidth to W on each column.
  • Maps Set Header_Label Item N to "L" -> Set psCaption to "L" on each column.
  • Removes legacy-only grid properties: Main_File, Wrap_State, peResizeColumn, psColumnsID.
  • Removes the standard Entry_Display boilerplate procedure.
  • Preserves all other content (other Set properties, nested objects) unchanged.

Group: Modernization

Parameter: "ANY"

Default: DbGrid,cDbCJGrid,cDbCJGridColumn

Three comma separated class names;

MyDbGrid - Your subclass of DbGrid,

MycDbCJGrid - Your subclass of cDbCJGrid,

MycDbCJGridColumn - Your subclass of cDbCJGridColumn

Fixes compiler message(s): 4537, 4533, 4345, 4328, 4298


RefactorDbListTocDbCJGridPromptList

Refactors legacy dbList selection lists to cDbCJGridPromptList prompt lists.

sParameter is 'OldListClass,NewGridClass[,NewColumnClass]' (empty = any class ending in "dblist", targets cDbCJGridPromptList/cDbCJGridColumn). Returns list objects transformed.

For each matching dbList object, scoped to the legacy object and never the whole file: - Renames the class to the new prompt-list class.

  • Converts the Begin_Row / Entry_Item list into individual column child objects.
  • Maps Set Form_Width Item N to W -> Set piWidth to W on each column.
  • Maps Set Header_Label Item N to "L" -> Set psCaption to "L" on each column.
  • Emits a one-time TODO header: the invoking object needs a Prompt_Callback handler

(the peUpdateMode pattern).

  • The surrounding dbModalPanel and the invoking object are NOT modified; only the list object itself is transformed. All other content is preserved unchanged.

Group: Modernization

Parameter: "ANY"

Default: dbList,cDbCJGridPromptList,cDbCJGridColumn

Three comma separated class names;

MyDbList - Your subclass of DbList,

MycDbCJGridPromptList - Your subclass of cDbCJGridPromptList,

MycDbCJGridColumn - Your subclass of cDbCJGridColumn

Fixes compiler message(s): 4537, 4533, 4345, 4328, 4298


RefactorGridToCJGrid

Refactors legacy non-data-aware Grid objects to a CJ grid class.

For each matching Grid object found across all selected files:

  • The scope is code within the legacy object, not the entire file.
  • Translates known properties to their cCJGrid equivalents
  • Renames the class to the new grid class.
  • Removes legacy-only grid properties: Wrap_State, peResizeColumn, psColumnsID.
  • Comments out the Entry_Display procedure body; any color Set properties found inside Entry_Display are translated and placed above the commented block.
  • Comments out legacy-only grid methods with a TODO marker.
  • Column sub-objects are NOT generated -- the non-data-aware column structure varies per use case and must be completed manually after refactoring.

sParameter must be a comma-separated list of 2 or 3 class names:

OldGridClass,NewGridClass[,NewGridColumnClass]

Example: "cMyGrid,cCJGrid,cCJGridColumn"

If sParameter is empty, any class whose name ends in "grid" (but not "dbgrid") is detected, and the standard DataFlex classes cCJGrid and cCJGridColumn are used as the target.

Returns the total number of grid objects transformed across all files.

Group: Modernization

Parameter: "ANY"

Default: Grid,cCJGrid, cCJGridColumn

Three comma separated class names;

MyGrid - Your subclass of Grid,

MycCJGrid - Your subclass of cCJGrid,

MycCJGridColumn - Your subclass of cCJGridColumn

Fixes compiler message(s): 4537


RefactorListToCJGrid

Refactors a legacy List (single-column item list) to a cCJGrid object. Subclasses the Grid-> cCJGrid engine, so a Send Add_Item fill method has its BODY converted (each Add_Item -> a TheData row) while KEEPING its name + parameters (it is called from other objects); a static

Item_List / On_Item block instead generates a Procedure LoadData + Activating. Generates one cCJGridColumn (header hidden) and preserves custom event procedures (OnChange, Mouse_Up, ...).

sParameter is a comma-separated list of 2 or 3 class names:

OldListClass,NewGridClass[,NewGridColumnClass]

If empty, any class ending in "list" (but NOT "dblist") is detected, targeting the standard cCJGrid / cCJGridColumn. Returns the total number of List objects transformed.

Group: Modernization

Parameter: "ANY"

Default: List,cCJGrid,cCJGridColumn

Three comma separated class names;

MyList - Your subclass of List,

MycCJGrid - Your subclass of cCJGrid,

MycCJGridColumn - Your subclass of cCJGridColumn

Fixes compiler message(s): 4537


RestyleDDOs

The naming style of data-dictionaries objects over time has changed.

The new style is:

Object o<tablename>_DD is a c<TableName>Datadictionary

They also have a switch so you can keep on using the legacy style name which is:

Object o<tablename>_DD is a <tablename>_Datadictionary

However before VDF12, this is how it looked:

Object <tableName>_DD is a <tablename>_Datadictionary

This caused tremendous headaches as due to the extra "o" we ended up with name clashes all over the place. Copying old code into new views/dialogs simply breaks and if your codebase has mixed styles then the compiler will not catch that.

A code nightmare.

Examples:

<TableName>_DD - o<TableName>DD (eDDStudioStyle)

<TableName>_DD - o<TableName>_dd (neDDNewStyle)

Group: Modernization

Parameter: "eDDStudioStyle, eDDNewStyle, eDDOldStyle"

Default: eDDNewStyle

Valid values; eDDStudioStyle - o<TableName>DD eDDNewStyle - o<TableName>_dd eDDOldStyle - <TableName>_DD
