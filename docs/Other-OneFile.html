  1. Refactoring Functions

Other - One File

Functions of type eOtherFunction operate on a whole file passed as a string array of source lines. The function returns the number of lines affected.


Cancel handling inside refactoring functions

If your refactoring function (especially the eOtherFunction and eOtherFunctionAll types) loops internally over many lines or files, you may want to let the user cancel without waiting for your loop to finish. Use:

Get pbUserCancelRequested of ghoEngine to bCancel

and exit your local loop when it returns True. Never call Get Cancel_Check of ghoEngine from inside a refactoring function - that is the engine's own cancel pipeline (it deactivates the status panel and shows the confirmation dialog), and calling it from your code silently consumes the cancel signal. The engine cannot then detect the cancel and the program appears to lock up while it continues processing the remaining files. The safe pbUserCancelRequested accessor is a read-only check with no side effects, so the engine's own cancel check at the file boundary still works correctly.


AddFunctionReturnsKeyword

Adds the mandatory "Returns <type>" clause to a legacy Function declaration that lacks it (compile error 4392). The return type is inferred from the function body - Function_Return literals and locally declared variables; mixed numeric widens to Number, any string makes it String. When nothing can be inferred the declaration gets "Returns Integer" plus a TODO (DFRefactor) comment to review. Declarations continued with ';' are handled.

Old compilers tolerated a bare declaration such as "Function Verify_Exit_Application"; a modern one rejects it, which is why a wizard-era shell can produce a wall of 4392s.

How the type is inferred: a Function_Return of a string, numeric or True/False literal classifies directly; a bare variable name is resolved against the function's own local declarations; several returns merge (Integer plus a decimal gives Number, anything plus a String gives String).

When the body gives nothing to read, the declaration gets "Returns Integer" and a TODO (DFRefactor) comment. That always compiles - any Returns type compiles where a bare declaration hard-fails, and the runtime converts on the caller side - but review it.

A declaration continued with ';' is joined before the check: one that already carries Returns on its continuation line is left alone, and a missing clause is added to the LAST physical line.

Group: Modernization

Fixes compiler message(s): 4392


ChangeAmbiguousCallToGet

Clears error 4544 by rewriting expression-style calls of an ambiguous-return-type method into a Get statement instead, changing no declarations. Pass the method name(s) as the parameter. Conservative: comment lines, continuation lines and object-less calls are left untouched.

Error 4544 comes from one message name declared with DIFFERENT return types across the workspace - a container class and a DEO both declaring Function Value, say - so the compiler cannot type an expression-style call of it and rejects every one. A couple of declarations can produce hundreds of errors in files that have nothing to do with those classes.

Example - If (Value(oFoo,"k") = 1) becomes three lines, the Variant temp declared right at the hoist site:

Variant vDfrGet1

Get Value of (oFoo) ("k") to vDfrGet1

If (vDfrGet1 = 1)

CAUTION: hoisting evaluates the call BEFORE the rest of the expression, so for a call with side effects that is a behaviour change. The alternative fix is to rename or type-align the few conflicting DECLARATIONS - a much smaller diff, but a design decision only the code's owners can make, which is why this is a suggestion.

Also left alone: unbalanced parentheses. Nested calls hoist innermost-first.

Group: Modernization


ChangeBeginEndConstraint

Converts legacy Begin_Constraints / End_Constraints blocks into a modern OnConstrain procedure. The ENTIRE block body (declarations, Get/If/Else and the Constrains they control, and any Report_* lines) moves verbatim and in order into 'Procedure OnConstrain' (opened with 'Forward Send OnConstrain') - nothing is reordered or moved out, since e.g. a Report_Index parameter can depend on logic earlier in the block. Comments are kept, blank lines dropped. A block with no matching End_Constraints is left untouched. A LONE End_Constraints with no Begin_Constraints (opening already migrated to Procedure OnConstrain) is expanded in place to End_Procedure.

Takes a whole source file as a string array.

Group: Modernization

Fixes compiler message(s): 4533


ChangeCmdlineCommandToFunction

Converts the retired sequential "Cmdline <var>" command to the cCommandLine class: each line becomes "Move (NextCmdLineArgument()) to <var>", backed by a small generated compatibility function at the top of the file that preserves the read-the-next-argument semantics ("" past the last argument). Pass one source file as a string array; returns the number of converted lines.

Why a shim and not a straight swap: the retired command read the NEXT space-delimited argument on every call - it is SEQUENTIAL - while the modern cCommandLine.Argument(i) is indexed, and the index a given line needs depends on the flow around it (the classic shape is a read-until-empty While loop). The generated NextCmdLineArgument() walks Argument(1..n) and returns "" past the last argument, which is exactly the legacy end condition, so such a loop still terminates the way it always did.

What is generated at the top of the file: Use cCommandLine.pkg, a global counter and NextCmdLineArgument() itself. It is #IFDEF-guarded and idempotent, so running the function twice over the same file does not add it a second time.

Limits: only the exact two-token command form is converted. A variable that merely happens to be named Cmdline elsewhere in a line, and the rare length-argument form, are left untouched.

Note that the old command still compiles silently on a modern DataFlex, so no compiler message points at it - Analyze Source is what finds it for you.

Group: Modernization


ChangeDfTimerTocTimer

Migrates legacy 'Object ... is a dfTimer' objects to the modern cTimer: swaps the class, drops Auto_Start_State/Auto_Stop_State/Timer_object, renames Timeout -> piTimeout, strips the OnTimer params, renames Timer_Active_State -> pbEnabled file-wide, and (when it relied on auto-start) injects 'Set pbEnabled to True'. Only Timer_Message-dispatch or param-using objects are left unchanged with a //TODO comment. Takes a whole source file as a string array.

A dfTimer that relied on auto-start (it never sets Auto_Start_State to False) does not start by itself once it is a cTimer, so the migration also injects 'Set pbEnabled to True' for it. An object left unchanged is marked with a TODO: comment because the Timer_Message dispatch and the OnTimer parameters need human judgment.

Group: Modernization

Fixes compiler message(s): 4537


ChangeLegacyClassToModern

Swaps a legacy class for its modern equivalent - object declarations, the Use line, and member renames - driven by a parameter, so one function covers any third-party package the runtime has since absorbed. Parameter: 'Old=New' first, then optional 'use:a.pkg=b.pkg', 'get:Old=New', 'send:Old=New', 'set:OldProp=NewProcedure' (a property that became a procedure). Reports anything it cannot attribute instead of guessing, and never re-bases a subclass. Pass one source file as a string array; returns the number of lines changed.

Group: Modernization


ChangeObjectFunctionCallToGet

Modernizes object-method calls written in the expression form (Name(Self, args)) to the Get command (Get Name args to dest) that DataFlex 26 requires. Auto-rewrites the clean 'Move (Name(Self[, simple args])) to dest' shape for methods declared (without Global) in the SAME file; every other occurrence (nested in a larger expression, complex arguments, non-Move host, first arg not Self) gets a //TODO for manual conversion. Global-function calls and names it cannot resolve here are left untouched.

Examples: 'Move (FormatValue(Self, sRaw)) to sOut' becomes 'Get FormatValue sRaw to sOut', and 'Move (RowCount(Self)) to iN' becomes 'Get RowCount to iN'.

Why it matters: the expression form keeps compiling until the release owns the same name (Split, for instance, arrives with DF26's runtime cRegEx) - the call then resolves to DataFlex's own function, the argument count or return type no longer fits, and you get error 4379 or 4544. The Get form is a message send, so it binds to your method again.

Group: Modernization

Fixes compiler message(s): 4544


ChangeParsePathPairToExtractFilePath

Collapses the legacy three-part path split into one modern call: "Get Parse_Path x to sPath" + "Get Parse_Drive x to sDrive" become "Get ExtractFilePath x to sPath", and any "(sDrive + sPath)" join becomes just sPath. A pair, not a rename - ExtractFilePath alone is not equivalent to Parse_Path, which strips the drive, trims the trailing separator and probes the disk. NOTE the result gains a trailing separator the old pair dropped. Refuses unless every use of the drive variable can be accounted for.

Before and after:

Get Parse_Path <spec> to <sPath> becomes Get ExtractFilePath <spec> to <sPath>

Get Parse_Drive <spec> to <sDrive> - line deleted

... (sDrive + sPath) ... becomes ... sPath ...

The old pair returned the folder with NO trailing separator; ExtractFilePath returns it WITH one. Wherever that string is displayed the extra separator becomes visible - no code is generated to strip it off again.

A pair whose drive variable is used in some way the converter cannot fully account for is left completely alone, so a refusal never leaves half a conversion behind.

Group: Modernization

Fixes compiler message(s): 4534


ConvertGosubToProcedure

Converts legacy Gosub subroutines to global Procedures - the SAFE subset only. A subroutine with self-contained control flow (plain Gosub_Returns, no boundary-crossing Goto) that only calls other convertible subroutines becomes 'Procedure <label>_Sub GLOBAL ... End_Procedure'; 'Gosub X' becomes 'Send X_Sub', 'Gosub_Return' becomes 'Procedure_Return', and 'ON..GOSUB' becomes a Case block of Send calls. Non-convertible subroutines are left untouched (run the Gosub/Goto report to see why). File-scope variables a converted subroutine uses are promoted to Global_Variable with a review marker; nothing is renamed or deleted. Takes a whole source file as a string array. Review the result - shared-variable lifetimes may still need thought.

Known limitations: a shared variable DECLARED inside a converted block becomes that Procedure's local - if a DIFFERENT converted subroutine also uses it, promote it by hand; and because detection is raw-line, a 'gosub' inside a multi-line string literal can in principle be mis-detected (the same trade the Gosub/Goto report makes). This is a conservative first version - verify the result on a real Gosub workspace; the change is reversible from the engine backup.

Group: Modernization


ConvertWin32TypeToStruct

Rewrites legacy Win32 'Type ... End_Type' blocks as modern Structs, with member types taken from the Windows SDK - the type name and all member names are kept, so existing X.member references and AddressOf() calls compile unchanged.

Only for Types in DFRefactor's Win32 catalog, and only where the member names match the SDK exactly; anything else is left untouched and reported.

Types the catalog does not know are left alone, and every refusal is reported as a run note naming the member that disagreed - a file that converts nothing still says why.

Only the DECLARATION is rewritten, and it is refused whenever the surrounding code would have to move with it: byte-level access (Put / GetBuff / Offset_of_Field / ZeroType) is a separate population this never touches - the Type-to-Struct report lists those for hand migration. Where the names match, the value is in the corrected TYPES: a legacy Word where the SDK says a pointer is exactly the x64 bug this app exists to find. Names that differ mean the legacy block flattened what the SDK nests, so the block is left as it is.

Group: x64 + Unicode


DeclareRefactoredIndicators

Declares (as #IFNDEF-guarded Global_Variable Boolean, spliced at the file top) the legacy NAMED indicators that the indicator converters rewrite to boolean-variable syntax but that have no 'Indicator X' declaration - otherwise the rewritten (X) / Move..to X is an undefined symbol. Reads the pre-conversion original, so it must run in the SAME pass as the converters (auto-selected with them). Skips built-ins (Found/FindErr/Err), SELECT, and names already declared 'Indicator X' in the same file.

Also renames bare expression READS of each shimmed OR 'Indicator X'-declared indicator to the gb-prefixed name (whole-word, string/comment-masked, skipped where a same-named local variable shadows it) - the declared names' declaration is ChangeIndicatorToBoolean's job.

Running it twice is safe: the #IFNDEF guard round each declaration makes the splice idempotent across files and conflict-free with ChangeIndicatorToBoolean's own guarded declarations, in any compile order, so no duplicate-global warning (4390) can result.

The read-rename exists because a bare expression read such as 'If (not(Login_Successful)) Begin' is already legal Boolean syntax that no converter touches - once the declaration and the write sites carry the gb prefix, that read would point at a name that no longer exists. Occurrences inside strings and comments, and '.'-qualified File.Field references, are never renamed, and a method that declares a local of the same name - or carries one in its signature - is left alone for its whole body.

Group: Modernization


DefineSelectMacro

Defines the bare 'Select' macro indicator left behind when ChangeLegacyIndicators / ChangeSquareBracketsIndicators modernise a legacy [Select] under eModernizeSelect. Splices a guarded SELECT-macro definition near the top of the file (an IFNDEF-guarded Replace) - NOT a Use line, since OldFMACCommands.pkg defines SELECT only via the REPORT macro. Scans the rewritten code for a bare Select, string/comment-safe; run it with those two, or after. No-op when none is found or the definition is already present.

The shim is spliced in after the leading Use/Include block, before the first real code line, so the macro precedes every use of it. The IFNDEF guard makes it idempotent and conflict-free: in a file that already defines SELECT - one using the legacy REPORT command macro, say - the shim compiles away to nothing.

A Use of OldFMACCommands.pkg is deliberately not added instead: that package defines SELECT only when REPORT is actually invoked, so a bare Select in a REPORT-less file would still fail to compile.

Detection reads each line with string literals masked and skips comment, blank, image and multi-line-string lines, so a SQL SELECT inside a literal or a continued block can never trigger it. The match is word-boundary aware: Selected, Selection and Select_State are not matched.

Group: Modernization

Fixes compiler message(s): 4345


GuardAnsiExternalFunctionWithWide

Declares the wide (...W) twin of an ANSI (...A) External_Function beside it, both under one #IF version guard, so the same DataFlex name works on a pre-Unicode and a Unicode DataFlex. Only where DFRefactor's Win32 catalog holds the twin - the wide parameter types come from the Windows SDK, not from swapping a letter. Call sites are not touched.

A declaration whose wide twin is not in DFRefactor's Win32 catalog is left alone rather than guessed at - the twin is never derived by swapping or stripping a trailing letter (that would invent SetClipboardDatW out of SetClipboardData). The wide form also takes different parameter types - LPCSTR becomes String, LPCWSTR becomes WString - so a letter swap would compile and then marshal wrongly.

Nothing is deleted: the original ANSI declaration is kept, and only the guard lines and the wide twin are added around it.

Group: x64 + Unicode


GuardDuplicateExternalFunctions

Wraps this file's External_Function declarations that the target DataFlex now declares itself in an #IF (!@ <= version) guard, so the duplicate compiles only on older releases - clearing the "already defined as an external_function" error 4390 without touching any call site. Reversible and idempotent; a ";"-continued declaration is guarded as one block.

Group: Modernization

Fixes compiler message(s): 4390


GuardRedundantGlobalFunctions

Wraps this file's own global functions that the target DataFlex now provides natively in an #IF (!@ <= version) guard, so they compile only on older releases - clearing duplicate-global error 4390 without touching any call site. Reversible and idempotent; only GLOBAL top-level declarations.

The original block is wrapped untouched, at its own indentation, between the version guard and its ENDIF - nothing is deleted or rewritten, and an already-guarded block is skipped on a re-run.

The "<=" is INCLUSIVE on purpose: your own release must keep compiling the home-brewed copy, because the native function does not exist there (a "< 191" guard would break a 19.1 app). A version this tool cannot read is refused - it changes nothing rather than write a wrong number into your source.

Only top-level declarations carrying the GLOBAL keyword are touched, and only names the target install itself ships; a same-named method inside a class is left alone.

CAUTION: on the newer release every call site silently switches to DataFlex's own implementation, which can differ in code page, error handling or edge cases - which is why this is a suggestion to review, not an automatic fix.

Group: Modernization

Fixes compiler message(s): 4390


MakeFileAutonomous

Adds a 'Use <package>' for every class a view, dialog, report or sortlist instantiates, so the file stands on its own. The class-to-package map is read from the DataFlex install and the workspace's own packages - never guessed from the class name. Program (.src) files are never touched. Classes defined in more than one package, or in none, are left alone.

New Use lines are added after the LAST existing Use, at column zero and without an #IFDEF wrapper, so nothing about the file's include order changes. A class defined in the file itself needs nothing; a class the index does not know, or one defined in more than one package (picking wrongly would compile the wrong implementation), is declined rather than guessed - the run summary names every class it declined, so the silence is accounted for.

Group: Modernization

Parameter: "ANY"

Default: vw;dg;rv;sl

The file extensions to act on, separated by ';' - leading dots optional; vw;dg;rv;sl - the default: views, dialogs, reports and sortlists, vw;dg - views and dialogs only.

A blank parameter falls back to the default. '.src' is always ignored: a program file is where include order is decided, and adding a Use there can change which file first pulls a package in.


RefactorBareGlobalsToGlobalVariable

Refactors bare command-level globals in a program shell to Global_Variable with the modern g-naming: 'String P_auto_login@ arg001' becomes 'Global_Variable String gsP_auto_login@ gsArg001', and EVERY in-file reference is renamed with it (string literals and comments are never touched). String->gs, Integer->gi, Number->gn, Date->gd, Boolean->gb; a type-letter camel prefix is absorbed (sCmdString -> gsCmdString); old size tokens (String arg1 1) ride along. FILE-scope declarations only - locals in Procedures/Functions, Struct members and anything inside an Object/Class are untouched, as are existing Global_Variable lines.

Returns converted declaration lines.

Group: Modernization


RefactorDbEditTocDbTextEdit

Refactors dbEdit data-aware memo controls to cDbTextEdit. Swaps the class on 'Object ... is a dbEdit' AND 'Class <sub> is a dbEdit' declarations (a subclass base is modernised too), renames Wrap_State to pbWrap inside the converted block, and TODO-flags legacy properties with no modern equivalent (scroll-bar states, Capslock_State). All shared DEO properties (Entry_Item, Server, Label, ...) pass through untouched. sParameter is 'OldEditClass,NewEditClass' (empty = 'dbEdit,cDbTextEdit'); pass e.g. 'dbEdit0,cDbTextEdit' to convert objects of your own dbEdit subclass. Returns declarations converted.

NOT a pure class swap - the lineages differ (dbEdit from Edit from DfBaseEdit, versus cDbTextEdit from cTextEdit from DFBaseTextEdit), so only the shared surface rides through: Entry_Item, Server, Size and Location, the Label family, Enabled_State, Read_Only_State, Value, Line_Count, peAnchors, Status_Help and the DEO verify_*_msg family. What differs: Wrap_State becomes pbWrap (NOT pbWordWrap), a text limit becomes piMaxChars, and Horizontal/Vertical_Scroll_Bar_Visible_State and Capslock_State have no modern equivalent at all - those are TODO-flagged for you to decide.

A default run modernises a subclass of your own at its DEFINITION: the base becomes cDbTextEdit and its objects keep the subclass name.

Group: Modernization

Parameter: "ANY"

Default: dbEdit,cDbTextEdit

Two comma separated class names;

MyDbEdit - dbEdit or your subclass of it,

MycDbTextEdit - cDbTextEdit or your subclass of it

UnicodeBufferPairToString

Collapses the DF 19.1 two-line buffer conversion "Move (OemToUtf8Buffer((AddressOf(sVar)),(Length(sVar)))) to aBuf" + "Move aBuf to sVar" into the one line "Move (OemToUtf8(sVar)) to sVar", for all four CharTranslate pairs. UnicodePointerToString

Unicode fix for compile error 4539: wraps the source of a bare "Move <pointer/address> to <string>" assignment in PointerToString(), and renames the DF 19.1 buffer idiom "Move (Utf8ToOemBuffer(sVar)) to sVar" to the String-returning sibling (Utf8ToOem & co, all four CharTranslate pairs). Conservative - rewrites only when the operand types are known from the local declarations/parameters. Pass one source file as a string array; returns the number of rewrites.

Error 4539 reads "Conversion from Pointer to String is not allowed, use PointerToString function"; an Address source trips the same error, so both qualify.

Examples:

  • Move aBuf to sResult becomes Move (PointerToString(aBuf)) to sResult
  • Move (Utf8ToOemBuffer(sLine)) to sLine becomes Move (Utf8ToOem(sLine)) to sLine

A Move is wrapped only when the source is a declared Pointer/Address and the destination a declared String in the SAME method; a buffer call is renamed only when it has one bare argument and both that argument and the destination are declared Strings or String parameters. A line whose operand types cannot be resolved from the declarations is left exactly as it was - a missed line is harmless, a wrong wrap is not.

A two-argument buffer call (AddressOf plus a length, the pointer-level API used on purpose) is never touched and needs a hand migration.

Group: x64 + Unicode

Fixes compiler message(s): 4539


UnicodeStringToPointer

Unicode fix for compile error 4539 (String to Pointer direction): rewrites a bare "Move <string> to <pointer>" into a MemCopy() call. Conservative - rewrites only when both operand types are known from declarations/parameters.

Pass one source file as a string array; returns the number of rewrites.

Before: Move <string var> to <pointer var>

After: Move (MemCopy(<ptr>, AddressOf(<str>), SizeOfString(<str>))) to iRFVoid

A throwaway Integer (iRFVoid) is injected once per method to receive MemCopy's return. The byte count uses SizeOfString, so it is encoding-aware; the buffer's own ResizeArray line is left untouched.

Group: x64 + Unicode
