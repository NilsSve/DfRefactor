Compiler Output

Compiler Output is the first of the three tabs at the foot of the window. It is the compiler's own listing, verbatim — the same text the DataFlex Studio would show you, with nothing added and nothing filtered out.


What fills it

Anything that runs the compiler:

  • Check on the dashboard — see Check - Compile + Analyze.
  • Compile on the compile bar, or F5 in the editor view, which saves the current file first.
  • Opening a .err file directly.

While the build runs the tab streams the compiler's live output and refreshes as it arrives, so a long compile is something you can watch rather than wait out. When the build finishes it re-reads the parsed .err, which is what turns each diagnostic into a row you can act on.


What is in it

A banner names the program, the full path of its .src, and the bitness being built. Under it comes one row per line of compiler output, each carrying a Studio-style icon:

  • a section-header icon on the ----...---- rows — ----Compiling, ----Compiler Error Summary----
  • its own icon on the ----Compile Finished in <n> seconds ---- row
  • a warning icon on a Warning <n> diagnostic
  • an error icon on an Error <n> diagnostic
  • a plain marker on everything else, including ----Executable written: and the - Total Warnings : / - Total Errors : summary

A clean build ends with ----Compile Finished and ----Executable written:. One with diagnostics puts its totals above the messages.


Working in it

  • Double-click a row to open that source file in the editor at the line. Rows that carry no source line — a link or manifest error, a summary line, a section header — have nowhere to go.
  • Right-click for Locate in Editor, Copy content to Clipboard, Copy ln number to Clipboard and Select All (Toggle).


When you need it, and when you do not

For an ordinary modernization lap, you do not. The Analyzer is the working list and the dashboard's findings are built from it, so the whole cycle can be run without ever opening this tab. Come here when:

  • The two counts disagree. The Analyzer drops diagnostics that have nothing to refactor and reports the number as a muted "excluded" pill. Those messages are real and this is where they still are — warnings in the Studio's auto-generated COM-proxy wrapper files, and link or manifest errors that carry no source line at all.
  • The build failed outright, so there was nothing to analyze. The reason is here, usually within the last few rows.
  • You want the compiler's own sentence rather than the analyzer's reading of it — worth doing before acting on anything marked Unknown.
  • You are checking what was actually built. The banner's bitness and the ----Executable written: line answer that, and they are the quickest way to catch a build that went somewhere unexpected.
