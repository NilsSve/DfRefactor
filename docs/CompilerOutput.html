Compiler Output

Compiler Output is the first of the three tabs at the bottom of the window. It shows the compiler's complete output, unchanged: the same text that the DataFlex Studio shows, with nothing added or removed.


What it shows

The tab is filled each time the compiler runs:

  • Check on the dashboard — see Check - Compile + Analyze.
  • Compile on the compile bar, or F5 in the editor view, which saves the current file first.
  • Opening a .err file directly.

While the compile is running, the tab shows the compiler's output as it arrives, so you can follow a long compile. When the compile has finished, the tab reads the .err file again, which turns each message into a row that you can work with.


The contents

A header shows the program, the full path of its .src file, and whether it is compiled as 32-bit or 64-bit. Below it, each line of compiler output is shown as one row, with an icon like the ones the Studio uses:

  • a section-header icon on the ----...---- rows — ----Compiling, ----Compiler Error Summary----
  • its own icon on the ----Compile Finished in <n> seconds ---- row
  • a warning icon on a Warning <n> diagnostic
  • an error icon on an Error <n> diagnostic
  • a plain marker on everything else, including ----Executable written: and the - Total Warnings : / - Total Errors : summary

A compile without messages ends with ----Compile Finished and ----Executable written:. When there are messages, their totals are shown above them.


Working in it

  • Double-click a row to open its source file in the editor, at that line. Rows without a source line, such as a link or manifest error, a summary line or a section header, cannot be opened.
  • Right-click for Locate in Editor, Copy content to Clipboard, Copy ln number to Clipboard and Select All (Toggle).


When you need it, and when you do not

For a normal modernization round, you do not need it. The Analyzer contains the list you work with, and the dashboard's findings are built from it, so the whole cycle can be done without opening this tab. Use this tab when:

  • The two counts are different. The Analyzer leaves out messages that cannot be fixed by refactoring, and shows their number as "excluded". Those messages are still real, and this tab shows them: warnings in the COM-proxy wrapper files that the Studio generates, and link or manifest errors that have no source line.
  • The compile failed completely, so there was nothing to analyze. The reason is shown here, usually in the last few rows.
  • You want to read the compiler's own message rather than the Analyzer's interpretation of it. This is a good idea before you act on anything marked Unknown.
  • You want to check what was actually compiled. The header shows 32-bit or 64-bit, and the ----Executable written: line shows where the program was saved. This is the quickest way to find a compile that was saved in an unexpected place.
