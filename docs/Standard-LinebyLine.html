Standard - Line by Line

Functions of type eStandardFunction work on one source line at a time. The engine calls each selected function for every line of every selected file. The line is passed by reference, and the function returns True if it changed the line.

AddUseFileExtension

Adds the default '.pkg' file extension to a Use statement that does not have one.

Example: Use cMyClass -> Use cMyClass.pkg

Use statements that already have an extension (.pkg, .vw ...) or a path in quotes are not changed, and neither is 'Use UI', the base package of character-mode DataFlex.

Group: Modernization

Fixes compiler message(s): 4535


ChangeCalcToMoveStatement

Replaces the legacy Calc, Calculate, MoveInt, MoveNum, MoveReal, MoveStr and MoveDate commands with the Move command.

The legacy commands still compile, but they do not work with the Studio's statement completion.

Example: Calc (iA + iB) to iC -> Move (iA + iB) to iC, and MoveInt iVal to iCount -> Move iVal to iCount

Group: Modernization

Fixes compiler message(s): 4533


ChangeCallToSend

Replaces the obsolete 'Call' command, which calls a procedure, with the modern 'Send' command.

Example: Call MyProc value1 value2 --> Send MyProc value1 value2

Group: Modernization

Fixes compiler message(s): 4533


ChangeChainToRunprogram

Replaces the obsolete 'Chain' command with 'Runprogram Wait'.

Example: Chain "report.exe" --> Runprogram Wait "report.exe"

Group: Modernization

Fixes compiler message(s): 4533


ChangeCodeJockReportToGrid

Renames the CodeJock names that DataFlex 23.0 changed from 'Report' to 'Grid', when cCJReportControl.pkg became cCJGridControl.pkg.

The Use line, the class names and the xtpReport/XTPReport constants are renamed together. The old names are defined only in OldcCJReportControl.pkg, so they must all be changed at the same time.

Examples:

  • Use cCJReportControl.pkg -> Use cCJGridControl.pkg
  • Class cMyGrid is a cCJReportControl -> ... is a cCJGridControl
  • Set piTheme to xtpReportThemeNone -> Set piTheme to xtpGridThemeNone

Only names with the CodeJock prefix are matched, so DataFlex's own Report classes and the ComReport* properties are never changed.

OldcCJReportControl.pkg itself is not changed. It still defines all the old names, so a Use of it still compiles, with the obsolete-package warning 4536. Converting the Use line without the names, or the names without the Use line, would break the code, so this function converts both on every line, and never changes the one file that defines the old names.

A workspace class whose name starts with cCJReport or xtpReport is renamed too. Only the base class is matched, so in 'Class cMyGrid is a cCJReportControl' the base class is renamed and the class's own name is kept.

Group: Modernization

Fixes compiler message(s): 4313, 4306


ChangeCurrent_ObjectToSelf

Replaces the legacy keyword 'Current_Object' with 'Self'.

Group: Modernization

Example: Define_Auto_Increment ITEM0030.Nr To DOCS0010.Nr -> Set Field_Auto_Increment Field DOCS0010.Nr File_Field ITEM0030.Nr

Group: Modernization

Fixes compiler message(s): 4533

ChangeExternalFunction32ToExternalFunction

Replaces the obsolete 'External_Function32' declaration with 'External_Function' (the '32' is removed).

Example: External_Function32 Foo "FooA" X.DLL ... returns integer --> External_Function Foo "FooA" ...

Group: Modernization

Fixes compiler message(s): 4533


ChangeFieldMainIndexToFileFieldIndex

Replaces calls of the obsolete Field_Main_Index with File_Field_Index.

Example: Get Field_Main_Index of hoDD iFile iField to iIndex -> Get File_Field_Index of hoDD iFile iField to iIndex

In a data dictionary, the answer then comes from the data dictionary that owns the table: -1 when the table is not in the data dictionary structure, and that data dictionary's Ordering is used. A method of your own that augments Field_Main_Index is not changed.

Group: Modernization


ChangeFileListCommandToAttribute

Replaces the obsolete Get_FileList and Set_FileList commands with the DF_FILELIST_NAME attribute.

Examples: Get_FileList sName --> Get_Attribute DF_FILELIST_NAME to sName; Set_FileList sName --> Set_Attribute DF_FILELIST_NAME to sName

The legacy commands have no 'to' keyword, so it is added together with the attribute name. The compiler makes the same change for these commands, so the behaviour does not change.

DF_FILELIST_NAME is a global attribute, so there is no 'of <File>.File_Number' part.

The indentation, the argument and any comment at the end of the line are kept as they are. Mentions in comments or strings are not changed, and neither is a line without an argument. Running it again is safe.

Group: Modernization

Fixes compiler message(s): 4533


ChangeGetAddress

Replaces the legacy GetAddress command with the AddressOf() function.

Example: GetAddress of sVal to aAddress --> Move (AddressOf(sVal)) to aAddress

Group: Modernization

Fixes compiler message(s): 4533


ChangeGetCurrentLockcountToAttribute

Replaces the obsolete Get_Current_Lockcount command with Get_Attribute DF_TRAN_COUNT.

Example: Get_Current_Lockcount to iLocks --> Get_Attribute DF_TRAN_COUNT to iLocks

The number is the same in both cases (how many transactions or locks are active, 0 when there are none), so the code that reads the variable afterwards does not need to change.

The indentation, the variable and any comment at the end of the line are kept as they are. Mentions in comments or strings are not changed, and neither is a line without a 'to <var>' ending. Running it again is safe.

The compiler never warns about this command, so Analyze Source is what finds it.

Group: Modernization


ChangeGetDateFormatToAttribute

Replaces the obsolete Get_Date_Format command with Get_Attribute DF_DATE_FORMAT.

Example: Get_Date_Format to iFormat --> Get_Attribute DF_DATE_FORMAT to iFormat

The value is the same in both cases (DF_DATE_USA (0), DF_DATE_EUROPEAN (1) or DF_DATE_MILITARY (2)), so the code that reads the variable afterwards does not need to change.

The indentation, the variable and any comment at the end of the line are kept as they are. Mentions in comments or strings are not changed, and neither is a line without a 'to <var>' ending. Running it again is safe.

Group: Modernization

Fixes compiler message(s): 4533


ChangeGetFileExistsToFileExist

Replaces the legacy Get_File_Exists function (from func.pkg) with the File_Exist command.

Example: Get Get_File_Exists sFileName to iExists --> File_Exist sFileName iExists

File_Exist has no 'to' keyword. Only the plain Get form is converted; a call in an expression, such as (Get_File_Exists(sF)), must be changed by hand.

The file argument (a variable, a string or an expression in parentheses) is copied exactly as it is, including its spaces, even when a string contains ' to ' or '//'.

A call with an 'of' clause, a line that continues with ';', and a line that does not end with 'to <var>' are not changed. Running it again is safe, because a converted File_Exist line is no longer a Get statement.

Group: Modernization


ChangeIfNotCommandToExpression

Replaces the legacy IFNOT command, and the two-word 'If Not' form, with an expression.

Examples: IFNOT Found Begin --> If (Not(Found)) Begin; If Not (Found) Begin --> If (Not(Found)) Begin (an unnecessary pair of parentheses is removed); If Not (iA = iB) Begin --> If (Not(iA = iB)) Begin.

A condition with several terms and no parentheses (If Not a eq b) is not changed, because putting only the first term inside Not() would change it. Lines with indicators in square brackets are not changed either; the indicator converters handle those.

Group: Modernization


ChangeIndexNumber

Changes index numbers in Find, vFind, Constrained_Find, Constrained_Clear and For_all commands from one number to another, for one table only. This is useful when the indexes of a table have been renumbered.

Both the Index.<N> form and the plain number are changed, in these places: the <N> after a mode keyword in Find, Send Find and Get Find (EQ, GT, LT, GE, LE, NE, FIRST, LAST, NEXT, PREV); the second argument of vFind <tbl> <N> <mode>; the <N> after 'by' in Constrained_Find and Constrained_Clear; and the <N> after by or down in For_all.

The table is recognised whatever its case, either by its name, or by a data dictionary object named o<TableName>_DD or o<TableName>_DataDictionary, the two common DataFlex naming conventions. Other naming conventions are not recognised; change those by hand.

The function's parameter is "<TableName>,<from>,<to>": the table name and two different positive numbers, for example "Customer,3,5".

Group: Other

Parameter: "ANY"

Three comma-separated values: the table name, the FROM index number, and the TO index number. Example "Customer,3,5" changes every

Index.3 / by 3 / vFind Customer.X 3 reference for the Customer table to use 5 instead. Both must be positive - DataFlex indexes are 1-based, and

-1 (recnum mode) is never modified.


ChangeIndicatorToBoolean

Replaces a legacy global Indicator declaration with a global Boolean variable. In DataFlex, an Indicator declaration is always global.

The new declaration is protected by #IFNDEF, so running the function again does not add it twice, and it cannot clash with the same name declared by DeclareRefactoredIndicators (warning 4390), whatever the compile order.

Example: Indicator User -> #IFNDEF User / Global_Variable Boolean User / #ENDIF (one block per name).

This function fixes the "Indicator. Use Boolean" form of compiler message 4538, which is about the declaration. Message 4538 is also reported for other forms: "Indicate. Use Move command" and "...without parentheses" are about where an indicator is used, and are fixed by ChangeLegacyIndicators and ChangeSquareBracketsIndicators.

Group: Modernization

Fixes compiler message(s): 4538


ChangeInToContains

Replaces the IN command with the Contains operator. The two values change places, and parentheses are added.

Example: If sSub in sAlphabet -> If (sAlphabet Contains sSub)

Group: Modernization


ChangeLegacyIndicators

Replaces the legacy 'Indicate' command and indicators with expressions.

Use it together with ChangeSquareBracketsIndicators. This function does most of the work, but it skips lines that contain Find, Send or Constrain; ChangeSquareBracketsIndicators converts those lines. Run both at the same time; this function then reports most of the changes.

Examples: Indicate Found as True -> Move True to Found; [~Found] Begin -> If (Not(Found)) Begin; [Select] Indicate Select as A Eq B -> Move (A = B) to Select; If [Not Found] Reread hTable -> If (Not(Found)) Reread hTable; Indicate X GROUP ANY [a b] -> Move (gba or gbb) to gbX.

An 'Indicate X as <expr>' statement that continues over several lines with ';' is converted across those lines.

Limitations: at most two indicators within one pair of square brackets, for example [Found Select]. A GROUP line that follows a bracket, a legacy condition or a ';' is not changed.

Group: Modernization

Parameter: "eLeaveSelect, eModernizeSelect"

Default: eLeaveSelect

eLeaveSelect keeps [SELECT] as-is (safe default). eModernizeSelect also needs DefineSelectMacro selected (it defines the SELECT macro).

Fixes compiler message(s): 4538, 4535


ChangeLegacyOperators

Replaces the legacy comparison operators gt, ge, lt, le, eq and ne with >, >=, <, <=, = and <>.

Operators in, for example, Find commands are not changed.

Example: If (iA Eq iB) -> If (iA = iB). LT LE EQ NE GT GE become < <= = <> > >=

Group: Modernization


ChangeLegacyShadow_State

Replaces Shadow_State and Object_Shadow_State with Enabled_State.

Example: Set Shadow_State [of oObject] to True -> Set Enabled_State [of oObject] to False, and Set Object_Shadow_State [of oObject] to True -> Set Enabled_State [of oObject] to False

Group: Modernization


ChangeLegacyTypeCast

Replaces a legacy cast with a type name, which DataFlex 26 does not accept (Handle(x), Pointer(x), DWord(x) and fifteen more), with the modern Cast(x, Type) form. Integer, String, Number, Date and Real are valid casts and are not changed.

This fixes error 4328, where the compiler names the type's internal name (LONGPTR for Handle, ADDRESS for Pointer) rather than the word in the source code.

Examples:

  • Send exportGridToExcel (Handle(Self)) becomes Send exportGridToExcel (Cast(Self, Handle))
  • Move (Pointer(0)) to p becomes Move (Cast(0, Pointer)) to p

Without this function the error is hard to understand: it names an undefined symbol called LONGPTR or ADDRESS, words that appear nowhere in the source code, with a hint about missing database fields and Type members.

When error 4328 names ADDRESS, the Analyzer does not offer this function as an automatic fix, because Address is also a common database column name, so the error is more often a missing field than a Pointer() cast. If you run this function, it still changes every Pointer() cast it finds.

Group: Modernization

Fixes compiler message(s): 4328


ChangeLegacyWorkspaceAccessors

Replaces a read of a legacy Workspace path with a read of the modern cWorkspace property.

Example: Get CurrentProgramPath of ghoWorkspace to sPath --> Get psProgramPath of (phoWorkspace(ghoApplication)) to sPath.

It covers all the paths of the obsolete Workspc.pkg (Data, Program, Bitmap, Help, AppSrc, DdSrc, SystemDf, Df and FileList). A name without a modern equivalent, such as CurrentModuleName, is not changed.

The modern properties read the opened .ws configuration, so check whether the code expects a separator at the end of a path when you review the result.

It is used together with RefactorWorkspaceTocApplication, which converts the Workspace object itself; this function changes the reads in all files.

Group: Modernization

Fixes compiler message(s): 4328


ChangeOemFileCommands

Removes the obsolete _Oem ending from the legacy file commands: File_Exist_Oem, EraseFile_Oem, CopyFile_Oem, Direct_Input_Oem, Direct_Output_Oem and Append_Output_Oem become File_Exist, EraseFile, CopyFile, Direct_Input, Direct_Output and Append_Output.

With the Unicode compiler, the OEM conversion that these commands make damages a path with non-ASCII characters, and does nothing for other paths.

Only the command itself is changed, so a variable with a similar name is not changed. Strings and comments are skipped.

Group: x64 + Unicode

Fixes compiler message(s): 4534


ChangeParseFileToExtractFileName

Renames the obsolete global function Parse_File() to ExtractFileName().

The result is the same for any real file name. The modern function only works on the text, while Parse_File checks the disk (through Parse_Path) to find out whether the last part is a folder.

One difference: for a path whose last part is an existing folder, Parse_File returned an empty value, and ExtractFileName returns the folder name.

The related Parse_Path is not converted, because ExtractFilePath does not return the same result: both the separator at the end and the drive letter are different.

Group: Modernization

Fixes compiler message(s): 4534


ChangeReturnToGosubReturn

Replaces the old Return command for subroutines with the modern Gosub_Return.

The two are the same command (Return is the spelling from DataFlex 1), so this is a rename that does not change what the code does, and it removes one warning per line.

Example: return -> Gosub_Return

It also makes ConvertGosubToProcedure possible, because that function finds where a subroutine ends by its Gosub_Return lines, and cannot convert a block without them.

Only a line whose first word of code is Return is changed. Not changed: Return used as an argument (Gosub_Return Return), a legacy name that ends with the word (cfg.key.return, p$return.max), a label that starts with it (return$flag:), Procedure_Return and Function_Return, and a one-line If (If (x) return), which must be changed by hand.

Group: Modernization

Fixes compiler message(s): 4533


ChangeSquareBracketsIndicators

Replaces legacy indicators in square brackets, such as [Found] and [FindErr], with expressions such as (Found) and (Not(Found)).

The 'Indicate' keyword itself is not changed; only the square brackets are.

Use it together with ChangeLegacyIndicators, which runs first but skips lines that contain Find, Send or Constrain. This function converts those lines, so it is normal that it reports few or no changed lines when both are selected.

Examples:

  • [Found] and [FindErr] indicator statements to (Found) and (FindErr).
  • [Found| Command -> e.g. If (Found) Command
  • [FindErr] Send Rebuild_constraints of oDD -> If (FindErr) Send Rebuild_constraints of oDD
  • While [Not Found] -> While (Not(Found)), and [Not Found] While likewise
  • If [Not Found] Reread hTable -> If (Not(Found)) Reread hTable
  • [~Found] Begin -> If (Not(Found)) Begin
  • [Found ~Found] Begin -> If (Found and Not(Found)) Begin
  • ifnot [SeqEof] Begin -> If (Not(SeqEof)) Begin

Limitation: a line that contains a GROUP or ALL indicator is not changed.

Group: Modernization

Parameter: "eLeaveSelect, eModernizeSelect"

Default: eLeaveSelect

eLeaveSelect keeps [SELECT] as-is (safe default). eModernizeSelect also needs DefineSelectMacro selected (it defines the SELECT macro).

Fixes compiler message(s): 4538, 4535


ChangeSysdate

Replaces the obsolete Sysdate and Sysdate4 commands with the modern CurrentDateTime() function.

Example: Sysdate dToday -> Move (Date(CurrentDateTime())) to dToday

The less common date and time form (Sysdate dDate tTime) gets a // TODO (DFRefactor) comment for a manual change, because its time variable cannot be set by the same CurrentDateTime() call.

Only the command is matched, so a variable named 'sysdate', or the word in other text, is never changed. A one-line If (If (x) Sysdate dDate) is left for a manual change; the TODO comment on the date and time form also stops the Analyzer from reporting that line.

Group: Modernization

Fixes compiler message(s): 4533

SplitCommandOutOfCondition

Moves a command out of a condition that it was placed in by mistake: 'If (a = b Command args)' becomes 'If (a = b) Command args'.

This causes compile error 52, "(operator) <COMMAND>", when a legacy one-line 'If a EQ b Command' was converted with the command inside the parentheses.

Only a line that starts with If, Else If, While or Until is changed, and only when its parentheses close at the end of the line and contain a simple comparison followed by a single word. All other lines are not changed.

Group: Modernization

Fixes compiler message(s): 52


SplitInlineIfElseLine

Splits If/Else statements written on one line into If/Else statements with a Begin/End block.

A line that ends with Break is not split, because that could change what the program does.

The function's parameter sets how the statement is split.

Example: If (iRetval = 0) Procedure_Return -> If (iRetval = 0) Begin / Procedure_Return / End

Group: Tidy Up

Parameter: "eSplitBySpaceAndSemicolon, eSplitBySemicolon, eSplitToBeginEndBlock"

Default: eSplitToBeginEndBlock

Valid values; eSplitBySpaceAndSemicolon - Split line with space and semicolon eSplitBySemicolon - Split line with semicolon eSplitToBeginEndBlock - Use a Begin/End block


UnicodeOemAnsiFunctions

Unicode fix for the legacy OEM/ANSI string conversions: changes ToOEM(x) to Utf8ToOem(x) and ToANSI(x) to Utf8ToAnsi(x).

Only whole words are changed, and running it again changes nothing, because Utf8ToOem is not changed again. Strings and comments are skipped.

Group: x64 + Unicode

Fixes compiler message(s): 4534


Win64AddressToPointer

64-bit fix: changes the type Address to Pointer, the replacement that the DataFlex documentation names, in local variables, struct members, Property and Global_Variable declarations.

Only whole words are changed, and running it again changes nothing. AddressOf, fields and a variable named "Address" are never changed. Parameter and return types are not changed.

Group: x64 + Unicode


Win64WindowLongFunctions

64-bit fix for the Win32 "long" functions that cut off pointers: changes GetWindowLong, SetWindowLong, GetClassLong and SetClassLong to their Ptr versions (GetWindowLongPtr and so on), which work with pointers in both 32-bit and 64-bit programs.

Only whole words are changed, and running it again changes nothing. Strings and comments are skipped.

Group: x64 + Unicode
